🎬 動画生成の仕組み

MCRangers の「動画を保存」機能 — ブラウザ内で演出を mp4 に書き出す技術メモ
ひとことで言うと
演出を実時計から切り離して1コマずつ手動で進め、各コマを1枚のcanvasに合成して H.264でエンコード、効果音は時刻だけ記録して後でまとめて合成し、 mp4にまとめてダウンロードする。サーバ送信は一切なく、すべて PC版 Chrome / Edge のブラウザ内で完結する。

★全体パイプライン

緑＝映像の流れ / 黄＝音声の流れ。ループ内で映像コマと音声イベントを集め、ループ後に音声合成とmp4化を行う。

1コマ送り再生(実時計を捨てる)

通常のプレビューは requestAnimationFrame + 実時計で動くため、PCが重いとフレームが飛んでカクつく。 録画では実時計を使わず、固定の dt(= 1/fps 秒)で1コマずつ手動で演出を進める。 1コマの描画に何秒かかっても、出力は常に等間隔フレームになり、滑らかな動画になる。 

const dt = 1 / fps;                 // 30 または 60
while (!finished) {
  recDirector.update(dt);           // 演出ロジックを 1コマぶん進める
  if (finished) break;              // 演出終了の空フレームは録らない（後述）
  fx.update(dt); screen.update(dt); stage.update(dt);   // 3D/エフェクト描画
  compositeFrame(...)               // 1枚に合成（次項）
  await rec.addFrame(comp)          // エンコード投入
}
最後のフレームの工夫: 演出が終わると Director は内部で「全員退場(cleanup)」してから終了通知する。 そのまま録ると誰もいない空フレームで終わってしまうため、終了を検知したら break し、 直前に記録済みの「全員が揃った余韻フレーム」を最終フレームにしている。

2レイヤー合成(3枚 → 1枚)

プレビューの画面は、実は独立した3つのレイヤーが重なってできている。録画では毎コマ、これらを1枚のcanvasに焼き込む。

① 3D本体 → ② 集中線・フラッシュ等のエフェクト → ③ ビネット・黒帯・タイトルの順に1枚へ。

3タイトルだけ作り直す(CanvasTitles)

プレビューのタイトル(名前・二つ名・決め台詞の吹き出し)は DOM + CSS で表示している。 しかし DOM は canvas に取り込めず、CSSアニメも実時計依存でコマ送りと同期しない。 そこで録画時だけ、同じ見た目をcanvasに直接描き直す CanvasTitles に差し替えている (ctx.titles を録画用に入れ替えるだけで、演出ロジックは無改造)。

このため 保存される動画は、名前・吹き出しなどの文字表現がプレビューと一部異なって見えることがある (フォント描画やアニメの再現が近似のため)。ダイアログにも同じ注記を表示している。

4映像エンコード(WebCodecs + mp4-muxer)

合成した各フレームを VideoFrame にして VideoEncoder(H.264)へ渡す。 出力された圧縮チャンクを mp4-muxer が mp4 コンテナに詰める。 mp4-muxer は録画時のみ CDN から動的importするので、通常起動は軽いまま。

  • 解像度に応じてコーデックを自動選択(avc1.640028 / 640033 など、isConfigSupported で確認)
  • エンコードキューが詰まったら待つ(バックプレッシャ制御)ので、巨大な動画でも破綻しない
  • 2秒ごとにキーフレームを挿入

5音声 — 「記録 → 後で合成」で完全同期

WebAudio はリアルタイムAPIなので、コマ送り(実時計より遅い/速い)と同時には鳴らせない。そこで2段階に分ける。

映像も音声も同じ「論理時刻」で組み立てるため、尺がぴったり一致して完全同期する。

録画中は makeRecSFX() という記録専用のダミーを ctx.sfx に入れておき、 効果音メソッドが呼ばれたら音名と論理時刻だけ配列に積む。録画後に renderAudio() が OfflineAudioContext 上でその時刻どおり全部スケジュールし、一気に PCM へレンダリングする。

6解像度・縦横比

ダイアログで選んだ縦解像度(720p〜4K)と縦横比から出力サイズ outW × outH を決め、 録画中だけ renderer・カメラの aspect・合成canvas をそのサイズに切り替える(録画後に元へ復元)。 シーンのカメラ演出は画面サイズに依存しない作りなので、解像度や比率を変えてもレイアウトは崩れない。

画面と違う縦横比(例: 9:16 の縦動画)を選ぶとカメラの画角が変わるため、整列など横長の演出は左右が少し見切れることがある。

7mp4化 → ダウンロード

全フレームのエンコードと音声の多重化が終わったら muxer.finalize() でバイト列を確定し、 Blob(type:'video/mp4') 化 → 一時的な <a download> を生成してクリック → ブラウザのダウンロードが走る。 サーバ送信は一切なく、すべてローカル完結。

📁どのファイルが何を担当するか

ファイル役割主な中身
js/recorder.js 録画エンジン FrameRecorder(映像/音声エンコード)、compositeFrame(合成)、renderAudio(音声合成)、downloadBlob
js/canvas_titles.js 録画用タイトル CanvasTitles — タイトル/吹き出しをcanvasに描き直す
js/app.js 進行・UI recordShow(コマ送りループ)、makeRecSFX、getRecordSettings、openRecordDialog
js/engine.js 効果音 SFX — useContext() / _recTime でOfflineに同期スケジュール
index.html UI 保存ダイアログ #record-dialog(編集画面・終了画面の両方から開く)
動作要件: WebCodecs / mp4-muxer を使うため PC版 Chrome / Edge 前提。 非対応環境ではダイアログを開く時点でその旨を通知する。
